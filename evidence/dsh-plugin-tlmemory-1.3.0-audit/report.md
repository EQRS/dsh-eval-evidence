## 二、任务契约与预注册

- 工具面：`tlmemory_save` / `tlmemory_query` / `tlmemory_delete` / `tlmemory_consolidate`（4 个；`registerMemoryTools` 注册）。
- 场景（8）：S1 保存后召回｜S2 **跨实例**召回（新建 MemoryDB 同文件）｜S3 作用域隔离（global 查询不得见 project 记忆）｜S4 删除后不再召回｜S5 中文关键词召回｜S6 批量 50 条后抽查 10 条｜S7 同路径同 rule 重复保存不重复（去重）｜S8 `consolidate dry_run` 可执行。
- 判分：结果串命中期望即 1；每场景 3 次重复；满 24。
- **不装组**：普通文件笔记（写 `notes.md` → 读文件/子串匹配 → 删行重写），即「不用记忆插件时的常规替代做法」。
- **装组**：真实调用插件 4 工具（DB 指向 `%TEMP%\tl-l3\exp\plug\tl.db`）。
- 说明：本件工具**无需 LLM**（save/query/delete 全本地），故本实验无模型调用、无随机性。

### 新观察 F1-tl（🟡 低）：数字 id 被静默丢弃 + 报错文案错误

- 现象：`tlmemory_query` 输出 `id: 2`（裸数字），`tlmemory_delete` 的入参 schema 声明 `id: string`；模型/调用方按输出传 `2`（number）时，代码 `typeof args.id === "string" ? … : ""` **静默置空**，随后返回 `拒绝删除：必须提供 id 或 rule_name 之一以指定目标` —— id 明明给了。
- 影响：删除失败且提示误导；不是数据损坏。
- 复现：`raw-sec.log` 第 5 段（数字 id）与第 2 段（字符串 id 成功）对照。

## 五、不适用条件

- 能力结论的**不装组是「文件笔记」替代方案**，不是「人完全无法做」；若部署里本来就没有文件读写能力，差值应更大；若已有成熟记忆系统，差值可能更小。
- 三项胜出是**语义层能力**（作用域/去重/合并）；文本召回质量（相关性排序、摘要质量）**未测**。
- 本件**未装载进真实 DSH**：`apply()` 还包含 turn 结束自动沉淀、compactor、LLM 提取等路径，这些**未测**（需真实宿主与模型）。
- 安全面：未抓包（数据外传靠静态代码阅读）；未做误删红队；DB 加密未评估；提示注入的**利用链**（不可信来源 → 自动提取 → 持久化 → 回灌）只验证了最后一环。
- 供应链只做静态 + tarball 完整性，未做依赖投毒实验。
